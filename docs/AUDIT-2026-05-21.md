# Debrief Audit — 2026-05-21

Audit run at v1.9.8 on `main`. Health + security + functional QA via static review and dependency audits. App was not run interactively (Electron desktop, no automated harness).

**Verdict:** Not ready for broader release. Recent fix sprint was sound, but audit found 3 critical security holes, 3 critical functional bugs (incl. silent data loss), and a broken dev environment.

**Composite health score:** 1.8 / 10 (typecheck partial, tests blocked by stale `node_modules`). Projected ~5–6 once env is repaired and `npm audit` advisories are addressed.

This file is the tracking checklist. Tick boxes as fixes land. Add a commit SHA next to each box so we can trace what shipped where.

## Tier 0 — block ship

Each item is small and surgical. Target: one branch (`tier0-critical-fixes`), one commit per fix.

- [x] **C-FN-2: Enable SQLite foreign keys.** `public/electron.js:197-207` — add `db.pragma('foreign_keys = ON')` after `new Database()`. Schema declares `ON DELETE CASCADE` on `project_transcripts`, `project_chat_conversations`, `project_chat_messages`, `project_analysis`, `transcript_segments`, `transcript_topics` — all currently no-ops. Add a regression test that deletes a project and asserts orphan rows are gone. _(branch `tier0-critical-fixes`, regression suite at `tests/database-cascades.test.ts`)_
- [x] **C-FN-1: Fix `change-database-location` filename mismatch.** `public/electron.js:964` writes `locallisten.db`; `initDatabase` (line 197, 207) opens `audio-scribe.db`. After "move," next launch opens empty DB in new folder — library appears to vanish. Either rename to `audio-scribe.db` or change `initDatabase` to use a single source of truth (preferred: a `DB_FILENAME` const). While here, decide whether sidecar/venv/vectordb move too (see H-15). _(Used `DB_FILENAME` const; H-15 deferred to Tier 1.)_
- [ ] **C-FN-3: Crash-proof `JSON.parse` on transcript columns.** `src/contexts/TranscriptContext.tsx:49-63` (and `getTranscript`, `searchTranscripts`) — wrap each of the 9 JSON columns in try/catch with sensible defaults. Same in `public/electron/vector-store.js:186, 230, 268` for the `speakers` column. One corrupt row currently empties the library silently.
- [ ] **C-SEC-2: Fix stored XSS in transcript search highlighter.** `src/components/ProjectCrossTranscriptSearch.tsx:49-54, 422, 450` — `highlightText` interpolates raw text into HTML, fed to `dangerouslySetInnerHTML`. Replace with a function returning React children (`<mark>` elements around matched substrings). HTML-escape first if you must keep the string-based shape.
- [ ] **C-SEC-1: Scope down `fs-*` IPCs.** `public/electron.js:1487-1526` — `fs-read-file`, `fs-write-file`, `fs-delete-file` accept any path. Restrict to paths under `app.getPath('userData')` (resolve + canonicalize + check prefix) or paths the user just selected via a dialog (track recent picks). Reject symlinks. Reject calls from non-top-frame senders.
- [ ] **C-SEC-3 + H-1: Kill the generic `db-query` IPC.** `public/electron.js:903-919` exposes raw SQL to renderer; `segments-update` (line 2148-2163) interpolates renderer-controlled column names. Audit renderer call sites, introduce per-domain RPCs (`transcripts.listByProject`, `segments.update(id, fields)` with column allow-list), remove the generic handler.

Once Tier 0 is merged, the app is shippable to friendly users (still has HIGH issues but no data-loss or RCE-equivalent paths).
